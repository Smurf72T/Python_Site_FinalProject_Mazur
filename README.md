## Описание

Сервис аренды одежды на Django: пользователи размещают объявления о сдаче
одежды в аренду, находят вещи по фильтрам, оставляют заявки на бронь,
общаются между собой и оценивают друг друга. Объявления публикуются только
после модерации.

### Реализованные функции

- **Размещение объявлений** — заголовок, описание, цена за сутки, залог,
  город, местоположение, фото, категория, размер, минимальный срок аренды.
- **Поиск и фильтрация** — по ключевым словам, местоположению, диапазону
  цены, категории и городу (с пагинацией).
- **Редактирование и удаление** — владелец может менять или удалять свои
  объявления; после редактирования объявление снова уходит на модерацию.
- **Аутентификация** — регистрация, вход и выход; создание и просмотр
  контактной информации доступны только зарегистрированным пользователям.
- **Модерация** — статусы `pending → approved/rejected`; модератор
  одобряет/отклоняет объявления на отдельной странице или в админке.
- **Обратная связь** — отзывы с оценкой (1–5) и автоматический пересчёт
  рейтинга владельца.
- **Дополнительно** — заявки на аренду с проверкой пересечения дат,
  расчёт общей стоимости, уведомления, личные сообщения, избранное,
  счётчик просмотров, личный кабинет.

## Технологии

- **Python 3.12 / Django 5.0**
- **PostgreSQL** (psycopg2), **Gunicorn**, **Pillow**
- **Nginx** (reverse proxy), **Docker / docker-compose** (5 контейнеров)
- **pytest + pytest-django + coverage** для тестирования

## Запуск через Docker

```bash
docker-compose up --build
```

Или на Windows:

```bash
docker-start.bat
docker-stop.bat
```

### Контейнеры

| Контейнер      | Порт  | Назначение                              |
|----------------|-------|-----------------------------------------|
| `rental_nginx` | 80    | Reverse proxy (единая точка входа)      |
| `rental_db`    | 5432  | PostgreSQL                              |
| `rental_backend` | -   | Основное приложение (Gunicorn)          |
| `rental_admin` | -     | Django Admin (runserver)                |
| `rental_tests` | -     | Автоматический запуск тестов с coverage |

### Полезные адреса

- **Сайт:** http://localhost/
- **Админка:** http://localhost/admin/ (логин `admin`, пароль `admin123`)
- **Результаты тестов:** `./test_results/report.html`, `./test_results/htmlcov/index.html`

### Переменные окружения (.env)

Пароль PostgreSQL и секретный ключ Django берутся из файла `.env`
в корне проекта. Пример `.env`:

```
POSTGRES_PASSWORD=postgres
SECRET_KEY=сгенерируйте-свой-ключ
```

`SECRET_KEY` используется контейнерами `backend` и `admin` для подписи
сессий и CSRF-токенов. Сгенерировать надёжный ключ можно так:

```bash
python -c "import secrets; print(secrets.token_urlsafe(50))"
```

Если `SECRET_KEY` не задан, docker-compose подставит небезопасное
значение по умолчанию — не используйте его в реальном деплое.

## Создание модератора

Модерация доступна пользователям с флагом `is_moderator` в профиле:

1. Войдите в админку http://localhost/admin/ (superuser `admin`).
2. Откройте **Профили** (Profile) нужного пользователя.
3. Выберите **Модератор** (is_moderator = ✓) и сохраните.

Также модератор может назначить права суперпользователя для полного доступа
к админке. Новые объявления попадают на страницу `/moderate/`.

## Запуск без Docker (локальная разработка)

```bash
python -m venv myenv
myenv\Scripts\activate        # Windows
source myenv/bin/activate     # Linux/macOS

pip install -r requirements.txt

# Настройте PostgreSQL и переменные окружения POSTGRES_*
python manage.py migrate
python manage.py fill_categories
python manage.py fill_cities
python manage.py runserver
```

## Тестирование

```bash
python -m pytest apps/ads/tests apps/users/tests -v
```

Тесты можно запустить через Makefile: `make test`, `make test-cov`,
`make test-html`. При старте Docker-стек сам запускает тесты в отдельном
контейнере.

## Структура проекта

